## 🎯 What Makes AlgoRevis Different?

Most developers preparing for technical interviews fall into the **"Memorization Trap"**: they solve hundreds of LeetCode questions, but 3 weeks later they either forget the solutions or remember the exact code without internalizing the underlying algorithmic pattern. When an interviewer tweaks the constraints or changes the story, they freeze.

> [!IMPORTANT]
> **OUR INSIGHT:** The real question is not *"can you re-solve a problem you have already seen?"* but *"can you apply the same pattern to a problem you have not seen?"*

> [!TIP]
> **OUR OPPORTUNITY:** Unite personal spaced repetition, isolated code execution, and sandbox-validated AI problem synthesis in one unified platform.

## 02 — The Dual-Question Paradigm (Saved Question ↔ AI Variant)

Every other platform forces an either/or choice: static LeetCode problems or an ungrounded AI playground. In **AlgoRevis**, both live side-by-side in the same workspace.

* **Question A (Saved):** Links to the LeetCode question in your personal folders, keeping your personal notes, difficulty, and original reference links.
* **Question B (AI Variant):** A new scenario needing the exact same underlying pattern. If Question A was *Two Sum*, Question B is a fresh pairing problem with a different story, constraints, and inputs.

> [!TIP]
> **OUR OPPORTUNITY:** You prove you understand the technique, not just the memorized LeetCode answer.

## 03 — Sandbox-Validated AI Generation

**The ChatGPT Flaw:** Practice questions generated by raw LLMs often come with hallucinated test cases, non-compiling starter code, or mathematically impossible constraints.

### Generation & Validation Pipeline

| Pipeline Step | What Happens |
|:---|:---|
| **1. User clicks Generate** | Request dispatched to backend with the saved question's pattern and semantic context. |
| **2. LLM generates** | Problem statement, constraints, unit test suite, and reference solution. |
| **3. Reference solution runs** | Executed inside an isolated sandbox runtime environment. |
| **4a. All tests pass** | Problem is verified and published to the user workspace. |
| **4b. Any test fails** | Automated fallback to the pre-validated benchmark catalog. |

> [!NOTE]
> **OUR OPPORTUNITY:** Every problem statement is solvable, with correct inputs, matching expected outputs, and validated edge cases.

## 04 — Intelligent Non-Repeating Spaced Repetition

* **Immediate Practice:** Next Random Question checks `excludeId`, so it never serves the question you are currently viewing if alternatives exist in that folder.
* **Next-Day Scheduling:** On solve, `nextReviewAt` advances forward. Tomorrow's scheduler picks only strictly overdue problems (`nextReviewAt <= now`).

## 06 — Multi-Channel Push Retention (Email + WhatsApp)

The hardest part of technical interview preparation is **consistency**. Traditional tools rely on you remembering to visit.

* Schedulers run per user, mapped to their active IANA timezone (`Asia/Kolkata`, `America/New_York`, `UTC`).
* At the chosen hour, it selects the daily challenge and delivers a direct deep link via **Email (Resend/SendGrid)** or **WhatsApp Cloud API**.
* The link opens the exact problem in the compiler workspace on phone or laptop, ready to code immediately.
